Color by role

A palette is a set of jobs, not a set of favorite colors. By the end you’ll name each color by its job, check every pair it touches, and keep meanings readable for people who don’t see red and green apart.

Name the job, not the color

Components never use a raw hex value. They use a role token, like --action or --muted, and only the token block knows the hex (C1). Change one value and every link updates; dark mode becomes a swap of values under the same names. Your v2 roles (B2):

RoleIts job
GroundThe page itself, most of what people see
FieldWhole chapters in dark green (Journey, the close)
SurfaceA small tone step that groups things without a box
InkEverything people read in sentences
MutedCaptions, notes, rail labels
PrimaryIdentity: your name, statements
ActionLinks, and the one filled button per screen
Highlight, Peach“Now” on the trail; text and the trail line on Field

Proportions, then colors

Plan how much of each, not just which (T5, C5). Ground is most of the page; your draft gives about 60% to Ground and 30% to Field. Ink carries the reading. Each accent gets exactly one job, and Action plus Highlight together stay under about 5% of a screen. That’s why a page with three orange things reads as noisy even when each one passes contrast.

Contrast is about light, not hue

WCAG measures contrast from luminance, how light a color is, because that works whatever hues a person can tell apart. The numbers come from vision research (W3C, “Understanding 1.4.3”):

  • 3:1 is the older standards’ minimum for text with typical vision.
  • 4.5:1 is 3 × 1.5: it makes up for the contrast lost with 20/40 vision, which W3C notes is typical around age 80.
  • 7:1 covers about 20/80 vision (1.4.6).

Your rules ask for more than the legal floor: body text 7:1, other text 4.5:1, large text (24px, or about 19px bold) and interface marks like icons, focus rings and control edges 3:1 (C2, P2). Two details people miss: ratios are never rounded, so 4.499:1 fails 4.5, and you never fade text with opacity. Use the Muted token, whose ratio you checked.

When two colors must mean different things

Red-green color blindness flattens greens and oranges toward the same brownish hue; what survives is lightness (C4). Your own green #2f6b4f and orange #b25a17 measure 1.0:1 apart under protanopia, which means no difference at all. So two rules:

  • Never color alone (C3). Every meaning color carries also has a word, icon, shape or position: links underlined, status as icon + word, a selected tab with weight and a bar. W3C’s “Use of Color” is the source.
  • Split by lightness (C4). Two colors that sit side by side as different meanings stay 3:1 apart under protanopia and deuteranopia simulation: a dark green with a light peach works; a medium green with a medium orange doesn’t.

Name each color by its job, check every pair it touches in both themes, and never let hue alone carry a meaning.

Practice

1. Body text is #6b7280 on white: 4.83:1.

  1. Fine: it passes AA everywhere
  2. Fails: gray is never allowed
  3. Fails your 7:1 body rule
  4. Fails: it is under 3:1

It passes WCAG AA’s 4.5:1, but your rule asks 7:1 for body text (C2, P2). Gray is fine for captions, at 4.5:1.

2. Why does WCAG ask for 4.5:1 rather than 3:1?

  1. Covers contrast lost to 20/40 vision
  2. Matches how print looks on paper
  3. Makes colorful brand palettes look calmer
  4. Screens in sunlight need double contrast

3:1 for typical vision, times 1.5 for the contrast lost with 20/40 vision, common in older readers.

3. A link color measures 4.496:1 against its background.

  1. Passes: it rounds up
  2. Passes if hovered first
  3. Passes in light theme
  4. Fails: ratios never round

W3C is explicit: no rounding. Nudge the color darker (or lighter, on dark) until it clears 4.5.

4. You make a caption muted with opacity: 0.6 on Ink.

  1. Fine if it measures 4.5
  2. Use the Muted token instead
  3. Lower it to 0.4 instead
  4. Add a text shadow behind

C2 bans fading text with opacity: the result changes with whatever is behind it, so its ratio is never checked. A Muted token has one checked ratio.

5. A green dot means “live”; an orange dot means “paused”.

  1. Add a word beside each
  2. Make the dots slightly bigger
  3. Swap to red and green
  4. Brighten both colors a bit

C3: the meaning needs a second cue. For a protanope these two dots can look identical.

6. Peach passes on Field, so you also use it for links on the cream Ground.

  1. Fine: Peach already passed once
  2. Add an underline to fix
  3. Light accents fail on light
  4. Use it only for headings

A ratio belongs to a pair, not a color. Peach on cream is far below 3:1; C5 bans light accents as text on light grounds.

7. One screen has two orange filled buttons and an orange headline.

  1. Orange needs a darker shade
  2. Underline the orange headline too
  3. Add a third orange element
  4. One accent job, one button

C5: Action means “click this”, so a headline in it lies, and one filled button per view keeps the main action obvious.

8. The selected tab differs from the others only by turning green.

  1. Use a brighter green instead
  2. Add weight and a bar
  3. Make unselected tabs light gray
  4. Animate the color change slowly

C3: weight plus an indicator bar survive any color vision. (Light gray tabs would also fail contrast.)

9. From lesson 7: you press “Send message” and nothing changes for six seconds.

  1. Consistency and standards
  2. Help and documentation
  3. Shows system status
  4. Prevents errors early

H1: past one second, show that work is happening; keep the label and add a spinner (I2).

10. From lesson 6: which outer margins pass?

  1. 24px left, 24px right
  2. 32px left, 48px right
  3. 12px left, 12px right
  4. 64px left, 64px right

An equal pair between 16 and 32px (T4, P6).
