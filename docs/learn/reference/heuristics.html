Usability heuristics

Jakob Nielsen’s ten, with the question each one asks and where your rules already cover it. Full rules: H1–H10 in the stage files, H11 in 5-ship.md. Source: NN/g, “10 Usability Heuristics for User Interface Design”.

Rules of thumb, not laws. A break needs a reason, and a review never replaces watching real people use the thing.

Three ideas worth keeping

  • Response-time limits (H1): under 0.1 s feels instant; past 1 s show that work is happening; past 10 s show percent done and a way to stop (Nielsen).
  • Slips and mistakes (H5): slips are autopilot errors, fixed with constraints, defaults and spacing. Mistakes come from a wrong mental model, fixed with clearer words and feedback.
  • Minimalist isn’t sparse (H8): a dense page passes if everything is relevant; a sparse one fails if something essential is missing.

Running a review (H11)

  1. Scope it: one task, one kind of user, one device.
  2. Walk the task once to learn it, then again to log problems.
  3. Log each: where · heuristic · what goes wrong · severity · fix.
  4. Best with 3–5 reviewers working alone, then merged; one reviewer misses many problems.
