Ten usability heuristics

Lessons 1–6 were about how a page looks. These ten are about whether people can use it. By the end you’ll run a heuristic review of a real task, name the heuristic behind each problem, and rate how bad it is.

Where they come from

Jakob Nielsen and Rolf Molich wrote the first version in 1990. In 1994 Nielsen refined them by analyzing 249 real usability problems, and they’ve barely changed since; NN/g last refreshed the wording in 2024 (NN/g, “10 Usability Heuristics”). They’re called heuristics because they’re rules of thumb, not laws: a phone menu behind a button breaks H6, and is often still the right trade. Your rules now hold them as H1–H10, each in the stage file where it gets designed, and H11, the review, in 5-ship.md.

Most of these were already your rules; each H-rule names the other rules that cover it (I2, ST3, P4…). Print-friendly version: Heuristics.

Three ideas from the deeper articles

  • Response-time limits (H1). Under 0.1 seconds feels instant. Past 1 second, show that something is happening. Past 10, show percent done and a way to stop (Nielsen).
  • Slips and mistakes (H5). A slip is autopilot: clicking the button next to the one you meant. Experts make them most. Fix them with constraints, defaults and spacing. A mistake comes from a wrong idea of how the thing works; fix it with clearer words and feedback. Either way, NN/g calls “user error” a design error (Laubheimer, “Preventing User Errors”).
  • Minimalist isn’t sparse (H8). A dense page passes if everything on it is relevant and findable; a sparse one fails if something essential is missing (Fessenden). Same lesson as Taste Skill’s: removing ornament without adding substance loses.

Each heuristic asks one thing from a different side: can this person see what’s happening, understand it, and act without guessing, remembering or getting stuck?

Running a review

A heuristic review is how designers use the ten (Moran and Gordon, NN/g):

  1. Scope it: one task, one kind of user, one device.
  2. Walk it twice: once to learn the task, once to log problems.
  3. Log each problem: where, which heuristic, what goes wrong, how bad, and a fix.
  4. Rate severity 0–4: not a problem, cosmetic, minor, major, catastrophe. Judge by how often it happens, how hard it is to get past, and whether it bites once or every time (Nielsen).

One reviewer misses many problems, so teams use 3–5 working alone and merge the lists. And a review is a first pass, not a replacement for watching real people use the thing.

Practice

Which heuristic does each one break most?

1. You click “Copy email”. It copies, but nothing on screen changes.

  1. Recognition over recall
  2. Shows system status
  3. Consistency and standards
  4. Help and documentation

H1: the action worked, but people can’t see that it did, so they click again or give up. Say “Copied” in place.

2. A save fails and the whole message reads “Error 400: ValidationException”.

  1. Prevents errors early
  2. Minimalist, relevant design
  3. Control and freedom
  4. Error recovery help

H9: say what’s wrong and how to fix it, in plain words, next to the cause. The code can stay as small secondary detail.

3. A photo viewer has no close button, Esc does nothing, and Back leaves the site.

  1. Control and freedom
  2. Shows system status
  3. Consistency and standards
  4. Flexibility and efficiency

H3: no marked exit. A labeled Close, Esc, and Back closing the overlay (I1, P3).

4. The tab says “Hikes”, its heading says “Trails”, and its URL says #explore-walks.

  1. Recognition over recall
  2. Minimalist, relevant design
  3. Consistency and standards
  4. Help and documentation

H4, internal consistency: one thing, three names. People wonder whether they’re three different things.

5. A date field rejects “10/21/2026”. Its message clearly says it wants 2026-10-21.

  1. Error recovery help
  2. Prevents errors early
  3. Recognition over recall
  4. Shows system status

H5: the message is fine, but the error shouldn’t exist. Accept the date however people type it and clean it up behind the scenes.

6. A phone app’s toolbar is six unlabeled icons, and you have to remember which is which.

  1. Recognition over recall
  2. Flexibility and efficiency
  3. Minimalist, relevant design
  4. Consistency and standards

H6: labels let people recognize instead of remember. Only a handful of icons (close, search, play) work without one.

7. In a tool you use daily, the export you run every morning is three menus deep, with no shortcut.

  1. Control and freedom
  2. Help and documentation
  3. Shows system status
  4. Flexibility and efficiency

H7: frequent users need a faster path (a shortcut, a remembered setting, a deep link) that novices never trip on.

8. A product page has a carousel, three badges and a testimonial marquee, and the price is below all of it.

  1. Consistency and standards
  2. Recognition over recall
  3. Minimalist, relevant design
  4. Matches real world

H8: every extra element competes with the one people came for. Also three slop tells.

9. A home-camera app’s setting reads “Enable MQTT keepalive override”.

  1. Matches real world
  2. Help and documentation
  3. Error recovery help
  4. Prevents errors early

H2: system words, not the customer’s. Say what it does for them (“Stay connected on weak Wi-Fi”). You know this one from work.

10. A new app opens with a seven-screen tour you must click through before you can use it.

  1. Shows system status
  2. Flexibility and efficiency
  3. Minimalist, relevant design
  4. Help and documentation

H10: push help that people dismiss unread, and here they can’t even skip it. Prefer hints at the moment of need, skippable in one action. It’s also a gate (P4).

Now rate each problem’s severity.

11. The Pay button sometimes does nothing for 8 seconds, so people tap again and get charged twice.

  1. 1: cosmetic
  2. 2: minor
  3. 3: major
  4. 4: catastrophe

Money lost, hard to undo, and it happens often enough to notice: fix before release. Two heuristics at once: no status (H1) and no prevention (H5).

12. One project name on your site is a slightly different green from the rest.

  1. 1: cosmetic
  2. 2: minor
  3. 3: major
  4. 4: catastrophe

Nobody is slowed down or confused. Fix it if there’s time.

13. At 390px your email link is hidden in a menu, so most phone visitors never find how to reach you.

  1. 1: cosmetic
  2. 2: minor
  3. 3: major
  4. 4: catastrophe

It hits the page’s main goal for many visitors, every time. LinkedIn still works as a way out, so major rather than catastrophe. It also breaks your Glance rule (P4).
