# Mission: Design principles for any UI

## Why
Phuru wants to design any interface (this portfolio, future apps, other sites) by his own
rules in `~/code/design-principles`, knowing why each rule exists well enough to apply it,
adapt it, or break it on purpose, and to judge what AI tools build for him.

## Success looks like
- Looks at any page, his own or generated, and names each slop tell and what replaces it.
- Writes an idea sentence for a new subject that passes the competitor test (T1).
- Picks the right container for a piece of content (V1) and says why.
- Builds a color token set with checked contrast and lightness-separated pairs, light and dark (C1–C6).
- Runs the `5-ship.md` checklist on a page and explains every fail.
- Explains each component in the portfolio v2 plan by the rules it serves.

## Constraints
- Learned alongside the live portfolio redesign; the site is the running example.
- Short lessons, one win each. Windows, no Node or Python.

## Out of scope (for now)
- Native iOS/Android conventions (`native.md`) and chart design (`data-display.md`, C7).
- React, Tailwind or any framework implementation.
